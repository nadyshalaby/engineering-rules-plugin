# 4.2 [route] Quick mode, the default

**Quick mode is the default route for every substantive prompt.** It keeps every check of
the full workflow and drops exactly three pieces of ceremony.

## What it keeps

| Phase | What runs |
|---|---|
| **1 Clarify** | In full: learn the ground, the goal anchor (5.2), the batched question round under the question contract (6.2), the repo brief (6.13), and the printed approach restatement that closes the phase. |
| **3 Implement** | In full: the ordered stages, the implement-and-test protocol (9.2), the file discipline, both scouts at the end of every stage. |
| **3b Debug** | In full, unchanged. Getting stuck is exactly when the protocol earns its cost. |
| **4 Verify** | In full: the Evidence Ledger, all three layers of the re-verify, the ship gate (11.3). |
| **5 Review** | In full: the five checks, the coverage ledger, the finding challenge (12.8), one fix pass, the same round cap. |
| **6 Finish** | Re-verify, land the way Phase 1 settled, the cleanup sweep, the law self-audit and the update log (16.13). |

## What it drops, and only this

1. **Phase 2's written plan, work-doc and gate.** The approach is restated in chat at the
   end of Phase 1 (section 6.1, step 6) and work starts on it. Quick mode has no user gate:
   the user's answers in the question round are the confirmation, and a user who wants to
   approve a plan first asks for full mode by name (4.1).
2. **Phase 2.5's spec review.** There is no written spec to audit.
3. **Phase 6's four-option landing menu.** The landing was settled by the handover question
   in Phase 1 (section 6.4, Q4) and Phase 6 executes that answer without a second menu.
   When the user said *"in place"* or *"just leave it"*, the changes stay in the working
   tree.

**Nothing else is dropped.** Not a review check, not the ship gate, not a verify layer, not
the evidence rules, not the question contract, not the scouts, not the cleanup sweep.

## The ledger in quick mode

The phase ledger (5.1) is printed in chat and re-printed at every phase boundary and at the end
of every implementation stage. It is not written to a file, which is why **quick mode
cannot be resumed across sessions.** Say so in one line when a task looks like it will span
sessions, and offer full mode. The six items are listed once, in section 5.1, and nowhere
else.

## Artifacts that quick mode keeps in chat

Full mode writes these into the work-doc; quick mode prints them and keeps them current:

- the goal anchor (5.2), restated at the top of every phase;
- the repo brief (6.13), built at the end of Phase 1;
- the Evidence Ledger and the ship-gate rows (11.1, 11.3);
- the coverage ledger and the decision table (12.2, 12.9);
- the law self-audit and the update log (1.7, 13.2).

Where the runtime can publish a page, quick mode may assemble these blocks into one scratch
markdown file under a fresh `mktemp -d` directory and publish it (7.3). It never writes
under `docs/work/`.

## Worktree

The workspace question in Phase 1 (6.4, Q2) decides it. When the answer is a separate copy,
create the worktree at the close of Phase 1, before any code, following the procedure in
section 7.1. Quick mode has no Phase 2, so Phase 1's close is where it happens.

## Promotion, and why it does not happen on its own

A user promotes a task to full mode by naming it. **No property of the task promotes it.**
Not the number of files, not that it touches auth, not that it spans packages, not that it
looks like it will take a while.

## Anti-rationalizations

| Thought | Reality |
|---|---|
| "This is big enough to deserve the full workflow." | Size is not the trigger. The user's words are. Offer full mode in one line; do not take it. |
| "Skipping the review is fine, the change is small." | The review is kept in quick precisely because small changes are where unreviewed defects hide. |
| "No work-doc means no ledger." | The ledger is printed instead of written. It still opens, still ticks, still gates. |
| "The ask is obvious, I can skip the clarify round." | Then the round is short and the restatement still prints. An ask that is obvious to you is the one you misread. |
| "Quick means fast, so the evidence bar is lower." | The evidence bar does not move. Quick removes ceremony, never proof. |
| "There is no gate in quick mode, so I can start coding right away." | No gate does not mean no clarify. Code before the question round is answered and the anchor is locked is a violation; the restatement at the end of Phase 1 is where code may begin. |
| "The user picked PR in Phase 1 but quick leaves things in the tree." | Quick drops the menu, not the landing. Phase 6 executes the answer the user already gave. |
