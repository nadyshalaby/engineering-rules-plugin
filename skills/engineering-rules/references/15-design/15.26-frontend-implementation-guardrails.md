# 15.26 [reference] Frontend implementation guardrails

## The mechanics under the design

The visual law says what good looks like; this file says what the build must do so the
look survives a phone, a slow GPU, a keyboard user and a dark room. Read it at Phase 3
before the first component of any UI-bearing task. Every rule is written stack-agnostic
first; the stack notes at the end name the conventions for the stacks generated pages are
most often built in. Where a rule is already a performance catalog row (3.1), the id is
cited so the perf scout (9.4) and the performance check (12.4) share it.

---

### Dependencies

- **Verify before importing.** Before importing any third-party package, read the project's
  manifest. If the package is missing, output the install command first, then the code.
  Never assume a library exists; an import hallucination is a boot failure (11.3).
- **Check the version before using a syntax.** A utility framework's major version, a motion
  library's import path, a component library's generation: read the manifest and match it.
  Do not use v4 syntax in a v3 project.
- **One of each.** One utility framework, one motion library, one icon family, one component
  system (15.21). A second of any is a finding.

### Viewport and layout mechanics

- **Full-height sections use `min-height: 100dvh`, never `height: 100vh` or `h-screen`.**
  The old unit jumps when a mobile browser's address bar shows or hides
  (`tell.layout.h-screen`).
- **Grid over flex math.** Never `calc(33% - 1rem)` column arithmetic; a grid with named
  tracks or `repeat()` does it reliably (`tell.layout.flex-math`).
- **Contain the page.** A container at 1200-1440px with auto margins on content-led pages;
  dense product surfaces run full-bleed with gutters by direction (15.4).
- **Standard breakpoints**, the spec's `platform.web.breakpoints`: 640, 768, 1024, 1280 or
  1440, 1536 when the project needs it.
- **Guard horizontal overflow.** The page root carries `overflow-x: hidden` (or clips) so an
  off-screen animation never introduces a horizontal scrollbar on a phone.
- **Logical properties** everywhere the spec sets `logicalProperties: required`:
  `margin-inline-start`, `padding-block-end`, `inset-inline-start`. Never `left` or `right`
  in a stylesheet that has to mirror (15.1).
- **Relative units.** Fixed pixel widths on layout wrappers are a tell
  (`tell.chrome.hardcoded-pixel-width`); type in `rem`, measures in `ch`, headlines with
  `clamp()`.

### Responsive verification

- **Test at five widths before calling a page done:** 375 (small phone), 390 (current
  phone), 768 (tablet), 1024 (small laptop), 1440 (desktop). The pre-flight (15.30) asks
  for the run.
- **Tap targets at least 44px** on touch; buttons full width on mobile where the direction
  allows; generous spacing between adjacent targets.
- **Body text at least 14px** on a phone, never shrunk to fit; headlines scale with
  `clamp()` and stay readable at 375.
- **No horizontal scroll at any width** is a hard pass condition.

### State for continuous values

- **Never store a continuous input in render state.** Pointer position, scroll progress,
  drag offsets and magnetic hover live in motion values or refs and drive transforms
  directly. A state update per frame re-renders the tree and collapses on mobile (15.25).
- **Local state for isolated UI; a global store only to escape deep prop-drilling.** A
  provider is a client boundary; keep it as high as it needs to be and no higher.

### Hardware acceleration

- **Animate `transform` and `opacity` only** (`perf.frontend.layout-animation`, 3.1). Never
  `top`, `left`, `width`, `height`, and never the colour of a large surface on scroll.
- **`will-change` sparingly**, only on the element about to animate, removed afterwards.
- **Grain, noise and blur live on fixed layers.** A grain overlay is a fixed,
  `pointer-events: none`, full-viewport pseudo-element above the content
  (`tell.asset.grain-on-scroller`); a backdrop blur sits only on fixed or sticky elements
  (a nav, an overlay), never on a scrolling container or a large content area
  (`tell.visual.default-backdrop-blur`). Both cause continuous GPU repaints elsewhere.
- **Isolate expensive motion in leaf components** that never re-render their parent (15.25).

### Reduced motion

- **Mandatory above `MOTION_INTENSITY` 3.** Every animation reads `prefers-reduced-motion`
  and collapses to static or opacity-only. The spec's `motion.reduced` line is the contract;
  the pre-flight runs the page with the preference on.

### Dark mode protocol

- **Dual-mode by default on consumer-facing surfaces.** Never light-only or dark-only
  without the user saying so. Print-emulating editorial surfaces are the one direction that
  may declare a single canonical mode without a second.
- **One token strategy per project, declared in the spec.** Either paired utilities
  (`bg-white dark:bg-zinc-950`) or semantic custom properties (`--surface`, `--text-primary`)
  swapped under `[data-theme="dark"]` or `prefers-color-scheme`. Never both.
- **The spec does not prescribe the dark colours; the brief and the brand do.** The spec
  enforces four things: contrast (AA for body, AAA the target for hero copy), **hierarchy
  parity** (if the CTA pops in light it pops in dark), **brand fidelity** (the primary stays
  recognisable; do not desaturate the brand into the dark theme), and **no pure `#000000`
  or pure `#ffffff`** (`tell.visual.pure-black`).
- **Default to the system preference** unless the brand insists on one mode; add a manual
  toggle when either mode would lose key brand expression, and do not make the sun-and-moon
  switch the reflex (`tell.chrome.sun-moon-toggle-reflex`).
- **Set the theme once at the root** (15.22, theme lock).
- **Test in both modes before finishing.** A page seen in one mode is half-reviewed; the
  pre-flight asks for both screenshots.

### Core Web Vitals

Targets, checked with a Lighthouse run before a page is called done:

| Metric | Target | What usually breaks it |
|---|---|---|
| LCP | under 2.5s | the hero image not prioritised or preloaded; a render-blocking script (`perf.frontend.blocking-scripts`) |
| INP | under 200ms | heavy work on the main thread during interaction; a scroll listener (15.25) |
| CLS | under 0.1 | images without dimensions (`perf.frontend.unsized-images`); fonts with no `font-display`; late-loading embeds |

- **Reserve space** for every image, font and embed.
- **Lazy-load everything below the fold** (`perf.frontend.no-lazy-loading`); route-level
  code splitting for heavy, rarely visited surfaces (`perf.bundle.no-code-splitting`).
- **Know what the motion and 3D libraries weigh.** A UI motion library is not tiny; a 3D
  engine is large. Load them where they are used, not in the shell.
- **Virtualise long lists** in product UI (`perf.frontend.missing-virtualization`).

### Fonts

- **Self-hosted or framework-loaded, never a third-party stylesheet link in production.** A
  font loads through the framework's font module or a self-hosted `@font-face` with
  `font-display: swap`, subset to the weights in use (`perf.bundle.unoptimized-fonts`).
- **The spec's `stack` ends in a generic family** and renders on a stock machine (15.3); the
  product may load the named face, the spec and preview never fetch it.
- **Tabular figures** wherever numbers align or update (`font-feature-settings: "tnum"`,
  the spec's `numeric` role).

### Icons and emoji

- **One family, one stroke width (1.5 or 2), one grid size**, monochrome, inheriting the
  current colour. Library glyphs only; never a hand-drawn icon path (15.23).
- **No emoji in markup, visible text or alt text** unless the brief asks for a chat-style
  voice.

### The z-index scale

- **Never arbitrary layers** (`z-50` on a card, `z-[9999]` on a tooltip,
  `tell.chrome.z-index-spam`). Reserve z-index for systemic layers and document the scale
  once in a constants file the whole project imports:

```ts
export const Z = { base: 0, raised: 10, sticky: 100, overlay: 1000, modal: 1100, toast: 1200, grain: 2000 } as const;
```

The grain overlay sits above everything and takes no pointer events.

### Semantic structure and accessibility

- **Landmarks, not div soup.** `nav`, `main`, `article`, `aside`, `section`, `header`,
  `footer`; `kbd` for keystrokes, `data` and `output` for values, `dl` for key-value pairs.
- **Every meaningful image has descriptive alt text**; decoration carries an empty alt
  (`tell.chrome.missing-alt`).
- **A visible focus ring** from the spec on every interactive element; `outline: none` with
  no replacement is a Critical finding (`tell.state.no-focus-ring`).
- **A skip-to-content link**, a `title` and description per page, social sharing tags, a
  branded favicon, a custom 404, the legal links (15.23, page chrome).
- **Contrast is computed, never asserted** (15.3, 12.5): every text token against its
  surface, every button label against its fill, every form string against its section.
- **Smooth anchor scrolling** (`scroll-behavior: smooth`) under `no-preference` only.

### Stack notes

For the stacks generated pages are most often built in. None of these relaxes a rule above.

- **React with a server-component framework.** Server components render static layouts
  only. Global state, providers, motion, scroll listeners and pointer physics live in
  client components marked at the top of the file, as isolated leaves. A provider wraps the
  tree from a client component.
- **Utility-first CSS.** Prefer the current major version; keep the older one only when the
  project already runs it. Configure the current version through its dedicated PostCSS or
  bundler plugin, not the legacy plugin name. Every colour, size and radius utility resolves
  to a spec token through the theme; an arbitrary-value utility carrying a raw hex is drift
  (12.5).
- **Motion.** The UI motion library imported from `motion/react` (the `framer-motion` name
  still resolves), a scroll engine only in leaves, never both in one tree (15.25).
- **Fonts.** The framework's font module, or `@font-face` with `font-display: swap`.
- **Icons.** One of `@phosphor-icons/react`, `hugeicons-react`, `@radix-ui/react-icons`,
  `@tabler/icons-react`, Heroicons; Lucide on request or when already a dependency.
- **Images.** The framework's image component with priority on the hero and lazy loading
  below the fold; explicit width and height on every image.
