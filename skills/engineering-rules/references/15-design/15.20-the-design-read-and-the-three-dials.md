# 15.20 [reference] The design read and the three dials

## Read the room before anything else

Read this file at Phase 1 for any UI-bearing task, before a direction is chosen (15.4) and
before a spec is authored (15.19). Most generated design is bad for one reason: the model
reaches for a default aesthetic instead of reading the brief. This file makes the reading
explicit, puts it on the record in one line, and turns it into three numbers every later
layout, motion and density decision is gated by.

---

### The six signals, read in this order

1. **Surface kind.** Landing (SaaS, consumer, agency, event), portfolio (developer, designer,
   studio), redesign (preserve or overhaul, 15.28), editorial or blog, product UI (dashboard,
   admin, settings, data table, editor), native screen set. The kind decides which parts of
   the page composition law (15.22) bind.
2. **Vibe words the user used, verbatim.** "Minimalist", "calm", "Linear-style", "Awwwards",
   "brutalist", "premium consumer", "Apple-y", "playful", "serious B2B", "editorial",
   "agency-y", "glassy", "dark tech". Map each to a direction slug with the vibe table in
   15.4. Never invent a thirteenth direction to hold a vibe word.
3. **Reference signals.** URLs linked, screenshots pasted, products named, brands they compete
   with. A reference feeds the extract protocol (15.5, Mode B or C) and the image-first
   workflow (15.31); it is never copied.
4. **Audience and its state of mind.** A procurement panel, a design-conscious consumer, a
   recruiter scanning a portfolio, an operator at 2am. The audience picks the aesthetic. Your
   taste does not.
5. **Brand assets that already exist.** Logo, colour, type, photography. On a redesign they
   are starting material, never optional input (15.28); on a greenfield build they are the
   identity the spec is written around.
6. **Quiet constraints.** Accessibility-first audiences, public sector, regulated industries,
   trust-first commerce, products for children. **A quiet constraint overrides every
   aesthetic preference above it**, and it usually names an official design system (15.21).

---

### The one-line read, declared before code

Before any code, any token and any dial, say in chat:

> Reading this as: **<surface kind>** for **<audience>**, with a **<vibe>** language, leaning
> toward **<direction slug, or the official system>**.

Three reads, so the shape is unmistakable:

- *Reading this as: B2B SaaS landing for technical buyers, with a Linear-style minimalist
  language, leaning toward `nordic-calm`.*
- *Reading this as: solo designer portfolio for hiring managers, with an editorial,
  kinetic-type language, leaning toward `editorial-print` with one scroll-driven moment.*
- *Reading this as: redesign of a public-sector service site, with a trust-first language,
  leaning toward GOV.UK Frontend (15.21), preserve mode (15.28).*

The read is the first line of the Phase 1 approach restatement (6.1), the first line of the
spec's Overview (15.3, written by 15.19), and the first line of the composition plan (15.22).
A page built without a declared read is a page built on a default.

---

### One question, never a dump

Ask exactly one clarifying question, through the wizard tool, and only when the read
genuinely forks: *"Closer to Linear-clean or Awwwards-experimental?"* When you can infer the
read from the signals, do not ask; declare it and go. The question contract (6.2) still
governs the shape of the one question you do ask, and a redesign's questions come from 6.9.

---

### Anti-default discipline

These are the defaults a model reaches for when it has not read the room. Each is refused
by name unless the read produced it:

| The reflex | What it is | Where the refusal is written |
|---|---|---|
| The AI-purple gradient, the glow | purple or violet accent, neon edge, mesh blob | 15.1, `tell.visual.ai-purple` |
| Centered hero over a dark mesh | the first hero shape the model ever learned | 15.22, `tell.hero.reflex-architecture` |
| Left text, right image | the second one | 15.22, `tell.hero.reflex-architecture` |
| Three equal feature cards | the feature row that means nothing | 15.22, `tell.layout.three-equal-cards` |
| Glass on everything | backdrop blur as a substitute for hierarchy | 15.1, `tell.visual.default-backdrop-blur` |
| Infinite micro-loops on every card | motion as decoration | 15.25, `tell.motion.loop-everywhere` |
| Inter on slate-900 | the default type on the default dark | 15.1, `tell.type.inter-default` |
| Serif because "creative" | Fraunces or Instrument Serif reached for as a mood | 15.1, `tell.type.serif-reflex` |
| Beige, brass and espresso because "artisan" | the premium-consumer palette every generated craft brand wears | 15.1, `tell.visual.premium-beige-brass` |
| An eyebrow above every headline | the templated rhythm of a page that labels itself | 15.22, `tell.label.eyebrow-everywhere` |

Reach past them deliberately, on the strength of the read.

## The three dials

After the read, set three numbers. Use exactly these names everywhere the numbers are
written; never invent an alias such as `LAYOUT_VARIANCE` or `ANIM_LEVEL`.

| Dial | 1 | 10 |
|---|---|---|
| `DESIGN_VARIANCE` | perfect symmetry | artsy chaos |
| `MOTION_INTENSITY` | static | cinematic, physics-driven |
| `VISUAL_DENSITY` | art gallery, airy | cockpit, packed data |

**Baseline `8 / 6 / 4`** for a marketing surface with no other signal. The baseline is a
starting point the read overrides, never a value to ship silently. Never ask the user to edit
a number; overrides happen in conversation, in their words.

### What each band means, in build terms

**`DESIGN_VARIANCE`**

- **1-3, predictable.** Symmetrical grid (12 columns, equal fractions), equal paddings,
  centered alignment. The honest choice for trust-first and data-first surfaces.
- **4-7, offset.** Negative-margin overlaps, mixed image aspect ratios side by side (4:3
  beside 16:9), left-aligned headers over centered data, asymmetric column spans (5+7, 4+8).
- **8-10, asymmetric.** Masonry, fractional grids (`2fr 1fr 1fr`), large empty zones
  (`padding-inline-start: 20vw`), elements that break the grid on purpose (15.1, compose
  with intention).
- **Mobile override, binding at 4 and above.** Every asymmetric layout above the `md`
  breakpoint collapses to a strict single column (full width, standard inline padding)
  below 768px. Horizontal overflow on a phone is a critical failure (15.22, 15.26).

**`MOTION_INTENSITY`**

- **1-3, static.** No automatic animation. `:hover` and `:active` states only. Reduced
  motion is the default state anyway.
- **4-7, fluid.** 200-400ms transitions on a decelerating curve, `animation-delay` cascades
  on load, one orchestrated reveal per view (15.1), transform and opacity only.
- **8-10, choreography.** Scroll-driven reveals, pinning, parallax, physics on hover. Every
  one of them motivated in one sentence, isolated, cleaned up and reduced-motion safe
  (15.25). A scroll listener on the window is banned at every band, not discouraged.

**`VISUAL_DENSITY`**

- **1-3, gallery.** Large section gaps (8-12rem), a single focal point per viewport, images
  and type doing the work. Expensive, clean.
- **4-7, daily app.** Standard product spacing (4-6rem between sections), balanced blocks.
- **8-10, cockpit.** Tight padding, no card boxes, 1px hairlines separating data, and every
  number set in the mono face with tabular figures (15.3, `numeric`).

### Where the numbers land

- **In chat**, on the line after the read: `Dials: variance 7, motion 6, density 4 (preset:
  landing, SaaS).` A dial left at baseline is written out too, with `(baseline)` after it,
  so a reader can tell a considered 8 from an unconsidered one.
- **In the spec**, in the optional `dials:` block of the frontmatter (15.3) and stated in
  the Overview prose, so a later session inherits the numbers instead of re-guessing them.
- **In the composition plan** (15.22), where every section's layout family is chosen
  against them.
- **In the pre-flight** (15.30): a page that claims `MOTION_INTENSITY` above 4 and does not
  move is broken, and so is a page that claims density 3 and ships a 20-row table.

### The rotation rule, the honest version of a random seed

One published variant of this idea has the agent simulate a random number to pick a hero
layout, so it stops choosing the first option every time. The problem is real: a model asked
for ten landing pages ships ten of the same page. The fix here is a written check rather
than a pretend dice roll.

Before committing the read, name what the previous project in this session or conversation
shipped, and pick differently unless the brief demands the same:

```
Rotated away from: display Fraunces, palette warm-craft, hero centered-over-image,
                   serif emphasis in headlines.
```

- The display face changes between consecutive projects (15.1: never converge).
- The palette family changes between consecutive premium-consumer projects (15.1, the
  seven alternatives to beige and brass).
- The hero architecture changes between consecutive marketing pages (15.27).
- A serif that was justified last time is not justified this time by inheritance.

When there is no previous project, write `Rotated away from: none, first project in this
session` so the line is never silently absent.
