# 15.21 [reference] The design-system map

## When the brief names a system, the system is the direction

Read this file at Phase 1 whenever the design read (15.20) names or implies a design system
that ships as an official package, whenever a quiet constraint (public sector, regulated,
accessibility-first) is in play, and whenever the extract protocol (15.5, Mode A) finds such
a package already in the project's manifest.

The rule is short. **Do not invent CSS for something that has an official package, and do
not pretend an aesthetic trend is an official system.** When the brief reads as one of the
systems below, install the official package, build with its components, and let the spec
record the mapping (15.3, the `system` key) instead of hand-authoring a lookalike token set.

---

### The map, from brief to package

| The brief reads as | Reach for | Why |
|---|---|---|
| Microsoft, enterprise SaaS, Office-adjacent dashboards | `@fluentui/react-components` or `@fluentui/web-components` | Official Fluent UI, Microsoft tokens, accessibility done |
| Google-ish product, Material-flavored | `@material/web` with Material 3 tokens | Official, themeable through Material Theming |
| IBM-style B2B, enterprise analytics | `@carbon/react` with `@carbon/styles` | Official Carbon, mature data-density patterns |
| Shopify app surfaces | Polaris web components, or Polaris React | Required for Shopify admin UI |
| Atlassian, Jira-style product | `@atlaskit/*` with `@atlaskit/tokens` | Official Atlassian design system |
| GitHub-style devtool or community page | `@primer/css`, or `@primer/react-brand` for marketing | Official Primer; the Brand variant exists for marketing pages |
| UK public-sector service | `govuk-frontend` | Legally and regulatorily expected |
| US public-sector, trust-first | `uswds` | Same |
| Fast local-business or agency MVP | Bootstrap 5.3 | Boring, fast, works |
| Modern accessible React foundation | `@radix-ui/themes` | Primitives plus a polished theme |
| Modern SaaS where you own the components | shadcn/ui (`npx shadcn@latest add …`) | You own the code and can customise it; never ship its default state |
| Tailwind-based modern SaaS or AI marketing | Tailwind v4 utilities with the `dark:` variant | The default for indie and small-team builds |

**One system per project.** Never mix Fluent React with Carbon in one tree; never import
shadcn/ui components into a Material 3 app. A second system found in the manifest is a
finding for the extraction report (15.5), not a feature.

---

### The honesty rule

- **Install and use the official package.** Do not recreate its CSS by hand. Do not import a
  system's tokens and then override ninety percent of them; at that point you have a custom
  system with a misleading dependency.
- **Verify the dependency before importing anything.** Read the manifest. If the package is
  missing, output the install command first (15.26). Never assume a library exists.
- **shadcn/ui is never shipped in its default state.** Radii, colours, shadows and type are
  customised to the project's spec; the default look is itself a tell
  (`tell.visual.shadcn-default`, 15.24).
- **Say in code comments what is borrowed inspiration and what is official material.** A
  hand-built approximation of a proprietary material is labelled as an approximation.

---

### When the brief is an aesthetic, not a system

For these there is no official package. Build with native CSS, the project's utility layer
and a maintained component library, honestly labelled, and map the aesthetic onto the
direction library (15.4) so its anti-tells apply.

| Aesthetic | Honest implementation | Nearest direction |
|---|---|---|
| Glassmorphism, frosted glass | `backdrop-filter`, layered borders, highlight overlays; a solid-fill fallback under `prefers-reduced-transparency`; only on fixed or sticky elements (15.26) | `soft-depth` for the layered feel without the blur; the labelled approximation below when blur is the brief |
| Bento, Apple-style tile grids | CSS Grid with mixed cell sizes; no library owns it | any; the bento rules are in 15.22 |
| Brutalism | native CSS, monospace, raw borders; no library | `brutalist-mono` |
| Editorial, magazine | serif type, asymmetric grid, generous whitespace; no library | `editorial-print` |
| Dark tech, hacker | mono plus one accent, terminal motifs; no library | `retro-terminal`, or `cyber-neon` when it glows |
| Aurora, mesh gradients | SVG or layered radial gradients; no library; the gradient discipline in 15.23 decides whether it is allowed at all | `cyber-neon` at most |
| Kinetic typography | native CSS animation, scroll-driven animation, GSAP for hijacks (15.25) | `brutalist-mono`, `editorial-print` |
| Apple Liquid Glass | **there is no official web package.** A web build is an approximation using `backdrop-filter`, layered borders and highlights, labelled as such | `soft-depth` |

### How the spec records an inherited system

A `DESIGN.md` written for a project on an official system is still a `DESIGN.md` (15.3),
because the project still needs one committed place where its choices within the system
live. What changes:

1. **The frontmatter carries a `system` block** naming the package, its version and where its
   tokens come from. The contract shows the shape.
2. **`direction` still names the nearest slug**, or `custom` with a rationale, so the
   direction's anti-tells still bind. GOV.UK reads as `swiss-grid`; Carbon reads as
   `data-dense`; Fluent and Material read as `soft-depth`; Primer reads as
   `industrial-precision` in its product form.
3. **Colour and type roles map to the system's own token names**, not to invented hex. A
   role the system does not provide is derived from it and marked as derived in the Colors
   prose.
4. **Components compose from the system's components.** The spec's component entries name
   which system component carries each role and which of the system's variants is used;
   they do not fork the system's CSS.
5. **The extract protocol's Mode A runs against the package's theme**, not against
   hand-written styles, and the drift it reports is drift away from the system.
6. **The design-conformance check (12.5) audits against the system's tokens.** A raw hex
   beside a system token is drift here exactly as it is anywhere else.

### Liquid Glass, honestly

**What is official.** Apple documents Liquid Glass inside its Human Interface Guidelines and
developer documentation for Apple platforms. It is a dynamic material used across Apple's
own UI, implemented by Apple's platform APIs and system components. It is not a public web
CSS package.

**What is not.** There is no `liquid-glass.css` from Apple for websites. A web build using
`backdrop-filter`, transparent backgrounds, layered borders, highlight overlays, gradients
and motion is web glassmorphism, an approximation. Label it as one in the code.

**The safer web approximation**, when the brief genuinely asks for it:

```css
.liquid-glass-web-approx {
  position: relative;
  isolation: isolate;
  overflow: hidden;
  border-radius: 999px;
  border: 1px solid rgb(255 255 255 / .32);
  background:
    linear-gradient(135deg, rgb(255 255 255 / .30), rgb(255 255 255 / .08)),
    rgb(255 255 255 / .12);
  backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  -webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .48),
    inset 0 -1px 0 rgb(255 255 255 / .12),
    0 18px 60px rgb(0 0 0 / .18);
}

.liquid-glass-web-approx::before {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  background:
    radial-gradient(circle at 20% 0%, rgb(255 255 255 / .55), transparent 34%),
    linear-gradient(90deg, rgb(255 255 255 / .18), transparent 42%, rgb(255 255 255 / .14));
  pointer-events: none;
}

.liquid-glass-web-approx::after {
  content: "";
  position: absolute;
  inset: 1px;
  border-radius: inherit;
  border: 1px solid rgb(255 255 255 / .14);
  pointer-events: none;
}

@media (prefers-color-scheme: dark) {
  .liquid-glass-web-approx {
    border-color: rgb(255 255 255 / .18);
    background:
      linear-gradient(135deg, rgb(255 255 255 / .16), rgb(255 255 255 / .04)),
      rgb(15 23 42 / .42);
    box-shadow:
      inset 0 1px 0 rgb(255 255 255 / .22),
      0 18px 60px rgb(0 0 0 / .42);
  }
}

@media (prefers-reduced-transparency: reduce) {
  .liquid-glass-web-approx {
    background: rgb(255 255 255 / .96);
    backdrop-filter: none;
    -webkit-backdrop-filter: none;
  }
}
```

`prefers-reduced-transparency` has uneven browser support; test it, and keep enough
contrast for the text to pass without the blur. The element is fixed or sticky, never a
scrolling container (15.26).

### Install commands

Reality anchors, so a spec never invents a package name.

```bash
npm install @material/web                                  # Material Web (Material 3)
npm install @fluentui/react-components                     # Fluent UI React (v9)
npm install @fluentui/web-components @fluentui/tokens      # Fluent UI Web Components
npm install @carbon/react @carbon/styles                   # IBM Carbon
npm install @radix-ui/themes                               # Radix Themes
npx shadcn@latest init && npx shadcn@latest add button card badge separator input   # shadcn/ui
npm install --save @primer/css                             # Primer CSS (product UI)
npm install @primer/react-brand                            # Primer Brand (marketing)
npm install govuk-frontend                                 # GOV.UK Frontend
npm install uswds                                          # US Web Design System
yarn add @atlaskit/css-reset @atlaskit/tokens @atlaskit/button @atlaskit/badge @atlaskit/section-message @atlaskit/card   # Atlassian
npm install bootstrap                                      # Bootstrap 5.3
# Shopify Polaris web components load from Shopify's CDN inside an app's HTML head, with the app's API key meta tag.
```
