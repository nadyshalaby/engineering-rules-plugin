# 15.28 [protocol] The redesign protocol

## Misreading the mode is where bad redesigns start

A redesign is not a greenfield build with an existing site in the way. It carries a brand,
an information architecture, rankings, analytics events and habits, and each of those is
something a rebuild can destroy without anyone noticing until later. This protocol runs
whenever the user says "redesign", "revamp", "modernise", "polish", "make it look better",
or the read (15.20) names an existing site. It sits between the redesign question bank
(6.9, which asks the questions) and the extract protocol (15.5, which recovers the tokens).

---

### Step 1, detect the mode

| Mode | Meaning | Dials (15.20) |
|---|---|---|
| **Greenfield** | No existing site, or a full overhaul approved in the user's words | baseline from the read |
| **Preserve** | Modernise without breaking the brand: audit first, extract the brand tokens, evolve gradually | match the existing site, motion +1 |
| **Overhaul** | A new visual language on top of existing content: greenfield for visuals, preserved content and IA | existing +2 variance, +2 motion, density matched |

When the mode is ambiguous, ask once, through the wizard tool: *"Should this redesign
preserve the existing brand, or are we starting visually from scratch?"* The redesign bank's
Q4b (6.9) is that question; its answer sets the mode and whether `DESIGN.md` is authored or
refreshed as a Phase 2 deliverable.

---

### Step 2, audit before touching anything

Document the current state before proposing a change. This is the redesign's repo brief
(6.13), and the extract protocol's Mode A (15.5) supplies the token half.

- **Brand tokens.** Primary and accent colours, the type stack, the logo treatment, the radii.
  Extract them before applying any colour rule: a brand that is already purple stays purple,
  and the AI-purple ban (15.24) yields to the brand with intent.
- **Information architecture.** The page tree, the primary nav, the key conversion paths.
- **Content blocks.** What exists, what is doing work, what is filler.
- **Patterns to preserve.** Signature interactions, a recognisable hero, the copy voice.
- **Patterns to retire.** The tells (15.24), broken layouts, dead links, generic stock
  imagery, performance traps (9.4).
- **The dial reading of the existing site.** Infer its `DESIGN_VARIANCE`,
  `MOTION_INTENSITY` and `VISUAL_DENSITY`; that reading is the starting point, not the
  baseline.
- **The SEO baseline.** Ranking pages, meta titles and descriptions, structured data, social
  cards, canonical URLs. **SEO migration is the number-one redesign risk**; write the
  baseline down before a single slug moves.
- **Existing accessibility wins.** Focus states, alt text, keyboard paths, contrast that
  already passes. A redesign never regresses them.
- **Analytics and integration hooks.** Element ids, form field names, event names that
  downstream tracking depends on.

The audit's findings are listed by the category checklist below, worst first, and shown to
the user before any fix (6.9 Q9 option D exists for exactly this).

---

### Step 3, the preservation rules

Binding in preserve mode, and in overhaul mode for everything that is not visual:

- **Do not change the information architecture** unless asked. Page slugs, anchor ids and
  primary nav labels stay stable, for search and for muscle memory.
- **Preserve the copy voice** unless a rewrite was asked for. Visual modernisation is not a
  content rewrite; the copy self-audit (15.23) still fixes broken strings.
- **Honour existing accessibility wins.**
- **Respect existing analytics events.** Do not rename buttons, form fields or section ids
  that tracking depends on.
- **Extract brand colours before applying the colour rules**, and apply the palette rules'
  override paths rather than their defaults.

---

### Step 4, the modernisation levers, in priority order

Apply in order and stop when the brief is satisfied. Each lever buys more than the one after
it and risks less.

1. **Typography refresh.** The biggest visual lift per unit of risk: a distinctive display
   face paired with a refined body (15.1), a proper scale, tighter display tracking, a
   capped measure, tabular figures in data.
2. **Spacing and rhythm.** Section padding, vertical rhythm, a container, consistent
   gutters, optical alignment.
3. **Colour recalibration.** Desaturate, unify the greys into one family, tint the shadows,
   keep the brand accent, lock it across the page.
4. **Hover, press and focus states.** The interface starts to feel alive with no layout
   change at all.
5. **The motion layer.** Dial-appropriate micro-interactions on existing components (15.25).
6. **Hero and key-section recomposition.** Restructure the top of the funnel with the
   composition law (15.22) and the vocabulary (15.27).
7. **Loading, empty and error states.** Makes the product feel finished.
8. **Full block replacement.** Only when a block is unsalvageable.

---

### Step 5, the decision tree

- **IA, content and SEO are sound** → **targeted evolution**, levers 1 to 5. Roughly
  seventy percent of the value at forty percent of the risk. This is the default and the
  recommended option in 6.9 Q9.
- **Visual debt is structural** (broken IA, no design system, broken mobile) → **full
  redesign** with strict content preservation.
- **The brand itself is changing** → **greenfield**, authored from 15.4 via 15.19.

---

### Step 6, what never changes silently

Never modified without explicit user approval, recorded in the anchor (5.2) as an
invariant:

- URL structure and route slugs.
- Primary navigation labels.
- Form field names or order (autofill and analytics break).
- The brand logo or wordmark.
- Existing legal, consent and cookie copy.

A change to any of these is a named acceptance-criteria bullet with its own proof row, never
a side effect of a visual change.

### The redesign audit checklist, by category

Run it in Step 2 and again as the pre-flight (15.30) at the end. Every line names a tell
(15.24) or a rule (15.22, 15.23, 15.26); a redesign that leaves one in place says so in the
update log.

**Typography.** Browser defaults or Inter everywhere; headlines with no presence (size,
tracking, leading); body wider than 65-75 characters; only two weights in use; proportional
figures in data; no tracking adjustments (negative on display, positive on small caps);
all-caps subheaders everywhere; orphaned last words with no `text-wrap`.

**Colour and surfaces.** Pure `#000` backgrounds; oversaturated accents; more than one accent;
warm and cool greys mixed; the AI-purple gradient; pure-black shadows; flat sections with
zero texture; perfectly even 45° gradients; inconsistent light direction; a random dark
section in a light page; empty flat sections with no depth or imagery.

**Layout.** Everything centered and symmetrical; three equal card columns; `100vh`
full-screen sections; flexbox percentage math; no container; equal-height cards forced by
flex; one radius on everything; no overlap or depth anywhere; identical top and bottom
padding (bottom often wants slightly more); the dashboard sidebar reflex; missing whitespace;
buttons not bottom-aligned in card groups; feature lists starting at different heights;
misaligned baselines in side-by-side elements; mathematically centered, optically wrong.

**Interactivity and states.** No hover; no press feedback; zero-duration transitions; no
focus ring; spinners instead of skeletons; no empty state; no error state, or `alert()`;
links to `#`; no current-page indicator; anchor jumps with no smooth scroll; animation on
layout properties.

**Content.** Generic names; fake round numbers; slop brand names; copywriting clichés;
exclamation marks in success; "Oops!"; passive voice; identical post dates; one avatar for
several people; lorem ipsum; Title Case headers.

**Components.** The generic card (border, shadow, white fill); always one filled and one
ghost button; pill-shaped "New" and "Beta" badges; accordion FAQs by reflex; three-card
testimonial carousels with dots; three pricing towers with the middle one taller; modals for
everything; only circular avatars; the sun-and-moon toggle; the four-column footer farm.

**Iconography.** Lucide or Feather by reflex; rocket and shield metaphors; inconsistent
stroke widths; a missing favicon; the stock "diverse team" photo.

**Code quality.** Div soup; inline styles beside classes; hardcoded pixel widths; missing or
generic alt text; arbitrary z-index; commented-out dead code; import hallucinations; missing
meta tags.

**Strategic omissions.** No legal links; no way back; no custom 404; no client-side form
validation; no skip link; no consent banner where required.

---

### The upgrade techniques, when a lever needs material

- **Typography.** Variable-font animation on scroll or hover; outline-to-fill transitions;
  text-mask reveals (15.27).
- **Layout.** Broken-grid asymmetry with calculated offsets; whitespace maximisation around
  one element; parallax card stacks; split-screen scroll.
- **Motion.** Staggered entry (translate plus fade, never everything at once); spring physics
  on every interactive element; scroll-driven reveals through masks, wipes and drawn paths;
  inertia scrolling only when the read is cinematic and the dial is 8 or above.
- **Surfaces.** Glass done properly (inner border, inset highlight, fallback); spotlight
  borders; a fixed grain overlay; tinted shadows.

Every technique obeys 15.25 and 15.26; none is applied because it is available.

---

### Rules that hold throughout

- **Work with the existing stack.** No framework or styling-library migration inside a
  redesign; that is a separate task with its own bank (6.9, refactor and migration).
- **Do not break existing functionality.** The triad and the ship gate (11.3) run after
  every stage, and the smoke leg drives the touched flow.
- **Verify every new dependency against the manifest** before importing it (15.26).
- **Read the utility framework's version** before touching its config.
- **Keep changes reviewable.** Small, targeted improvements in dependency order over one
  big rewrite; every hunk traces to a lever the plan named (`SKILL.md` 1.6, surgical
  changes).
- **The spec is refreshed, never duplicated.** Preserve mode runs 15.5 REFRESH; overhaul
  mode authors through 15.19 with the audit's brand tokens as the identity.
