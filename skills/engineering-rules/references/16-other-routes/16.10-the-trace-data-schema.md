# 16.10 [contract] The trace data schema

The explore-feature route (16.9) produces one file the session authors, `trace.json`, and
one file a script derives from it, `excerpts.json`. The page template renders the two
together. This file is the whole contract for both. Field names are exact, the caps are
hard, and `verify-trace.sh` refuses a trace that breaks any rule marked **verified**, so a
page can only ever be built from a trace the working tree agreed with.

## Where the files live

Everything the route writes goes under one scratch directory, never under the explored
repository:

```
<scratch>/explore-<slug>/
├── trace.json          authored by the session, this schema
├── excerpts.json       written by scripts/verify-trace.sh, never by hand
├── capture.meta.json   written by scripts/capture-run.sh at start: the trace, mode, command
├── capture.jsonl       written by the sink while the command runs, one event per line
├── capture.log         the command's output in live mode
├── capture.pid         the live process, until --stop
├── capture.json        written by scripts/capture-run.sh after the run, never by hand
└── page.html           written by scripts/build-page.sh, the artifact that is published
```

The four `capture.*` files exist only when the route ran the capture step (16.9, step 6b);
a page is built with or without them.

`<scratch>` is the runtime's scratchpad directory when it names one, else `mktemp -d`.

## trace.json, top level

```json
{
  "version": 2,
  "title": "Send Estimate Path",
  "entry": { "label": "POST /api/work-orders/:id/send-estimate", "kind": "http",
             "trigger": "A workshop user presses Send estimate on a work order." },
  "root": "/abs/path/every/file/is/relative/to",
  "summary": "Two or three plain sentences: what happens end to end.",
  "files": [ { "path": "SyanatBackend/src/…/estimates.controller.ts", "layer": "controller",
               "role": "Parses the body and calls the one service method." } ],
  "hops": [ … ],
  "pseudocode": [ { "step": 1, "text": "Validate the body against SendEstimateSchema.", "hops": ["h2"] } ],
  "branches": [ { "at": "h4", "name": "estimate already sent", "trigger": "status !== 'draft'",
                  "taken": false, "outcome": "throws EstimateAlreadySent, the handler answers 409" } ],
  "failure": { "title": "When the customer has no email address",
               "hops": ["h6"], "steps": ["…", "…"] },
  "shapes": [ { "at": "h2", "label": "request body", "shape": "{ mode: 'email' | 'whatsapp' }" } ],
  "decisions": [ { "text": "…", "alternative": "…", "hops": ["h5"] } ],
  "questions": [ { "q": "…", "a": "…", "hops": ["h4"] } ],
  "unreached": [ "The WhatsApp mode; only mode = 'email' was walked." ],
  "related": [ { "label": "Chapter 2: the email leaf", "url": "https://…" } ]
}
```

| Field | Type | Required | Rule |
|---|---|---|---|
| `version` | int | yes | `2`. **verified** |
| `title` | string | yes | The page's name: a short noun phrase, 2 to 4 words, ≤ 40 characters, specific to this feature. Never a sentence, never a name plus an explainer. **verified: ≤ 40 characters** |
| `entry.label` | string | yes | The entry point exactly as the user named it, or as the code names it when the user's words were resolved (16.11, §1). |
| `entry.kind` | enum | yes | `http`, `cli`, `job`, `ui`, `event`, `other`. **verified** |
| `entry.trigger` | string | yes | One sentence: what a person or system does to fire it. |
| `root` | string | yes | Absolute path every `file` is relative to: the directory the route ran from, a repository or a workspace of repositories. **verified: is a directory** |
| `summary` | string | yes | One to three sentences, plain words, the whole path in miniature. |
| `files` | array | yes | Every file a hop cites, once each, with `layer` and a one-line `role`. **verified: every hop file listed, every listed file used** |
| `hops` | array | yes | The path, in execution order. 1 to 40 entries; hop 0 is the entry. **verified** |
| `pseudocode` | array | yes | The algorithm in 1 to 12 numbered steps, each pointing at one or more hops. **verified: hop ids resolve** |
| `branches` | array | yes | Every decision point met on the path, taken or not. May be `[]` when the path has no conditional, which is rare and is said in `unreached`. An entry may carry `line`, the line inside the hop at `at` where the condition sits, so a page with a capture can show the outcome observed on that line beside the one the trace declares. **verified: `at` resolves** |
| `failure` | object | yes | The one failure path most worth knowing: `title`, `hops`, `steps`. **verified: hop ids resolve** |
| `shapes` | array | no | The payload at each boundary, typed pseudocode. **verified: `at` resolves** |
| `decisions` | array | no | The two or three design decisions that shaped the path, each with what the alternative would have cost. **verified: hop ids resolve** |
| `questions` | array | yes | 3 to 5 comprehension questions with their answers; the page hides answers until revealed. **verified: count, hop ids resolve** |
| `unreached` | array | yes | What this page does not cover: a mode not walked, a branch parked, a leaf not opened. `[]` is allowed only when nothing was left out. |
| `related` | array | no | Other pages: a chapter, the previous version's URL. |

### files[]

| Field | Rule |
|---|---|
| `path` | Relative to `root`, forward slashes, no `./`, no `..`. |
| `layer` | One of `route`, `controller`, `middleware`, `service`, `repository`, `schema`, `type`, `lib`, `ui`, `external`, `other`. Use the repository's own vocabulary as the tie-breaker (a Rails model is `repository`, a Hono middleware is `middleware`). The page groups chips by layer. |
| `role` | One line, from the code: what this file is for on this path. |

## hops[]

A hop is one **frame** on the path: a function, handler, middleware, schema or type the
path enters, with the place it was entered from. The page draws frames as the call stack,
the call sites as sequence-diagram arrows, and each frame's excerpt as a diff-style pane.

```json
{
  "id": "h3",
  "title": "Service refuses to resend a sent estimate",
  "file": "SyanatBackend/src/modules/work-orders/estimates/services/estimates.service.ts",
  "symbol": "sendEstimate",
  "line": 41,
  "evidence": "export async function sendEstimate(",
  "range": [41, 78],
  "kind": "call",
  "from": "h2",
  "call": { "file": "SyanatBackend/src/…/estimates.controller.ts", "line": 27,
            "evidence": "await sendEstimate(repo, { workOrderId, mode })" },
  "why": "The status gate lives here and not in the controller because every caller of the service, the CLI included, must be refused the same way.",
  "invoked": [41, 42, 43, 47, 48, 52, 61, 77],
  "returns": "{ sentAt: Date, channel: 'email' }",
  "throws": [ { "error": "EstimateAlreadySent", "when": "the work order is past draft" } ],
  "status": "verified"
}
```

| Field | Type | Required | Rule |
|---|---|---|---|
| `id` | string | yes | `h<n>`, unique, `h0` is the entry. **verified: unique, `h0` first** |
| `title` | string | yes | What happens at this hop, verb first, ≤ 60 characters. **verified: length** |
| `file` | string | yes | Relative to `root`; must exist and be a file. **verified** |
| `symbol` | string | yes | The enclosing declaration's name as written in the code (`sendEstimate`, `SendEstimateSchema`, `buildRoutes`). |
| `line` | int | yes | The line the frame is entered at: the declaration line of `symbol`, or the registration line for an entry hop. 1-indexed. **verified: within the file** |
| `evidence` | string | yes | A literal substring of that exact line, long enough to be unmistakable (the declaration head, the registration call). Case-sensitive, whitespace as in the file. **verified: found on `line`** |
| `range` | `[int, int]` | yes | The excerpt shown for this frame, inclusive, 1 to 200 lines, containing `line` and every child hop's `call.line`. Narrow a long function to the part this path runs. **verified: bounds, contains `line`, ≤ 200 lines, contains every child call line** |
| `kind` | enum | yes | `entry`, `call`, `middleware`, `dispatch`, `io`, `external`, `type`. `io` (a query, a request, a file, a queue) and `external` (a library the repository does not own) are leaves: the trace stops there. `type` is a schema, DTO, interface or class referenced on the path. **verified: enum** |
| `from` | string or null | yes | The hop this one was entered from; `null` only on `h0`. Must name an earlier hop. **verified** |
| `call` | object or null | yes | Where the parent enters this hop: `file`, `line`, `evidence`, the same rules as the frame's own. `null` only on `h0`. The line must sit inside the parent's `range`. **verified: file, line, evidence, inside the parent's range** |
| `why` | string | yes | One or two sentences: why this hop exists on the path, derived from the code, `file:line` inline where it helps. Never from a comment or a doc (16.11, §2). |
| `invoked` | int[] | no | The lines of `range` that run on this path; the page dims the rest and counts them in the excerpt's header. Give it only when the code decides it; omit it when a condition depends on runtime state you did not pin, and say so in `branches`. When given, it always holds `line` and every child hop's `call.line`, and never a blank or comment-only line. **verified: subset of `range`, holds `line` and every child `call.line`, no blank or comment line** |
| `returns` | string | no | What leaves this frame, typed pseudocode. Drawn as a dashed return arrow. |
| `throws` | array | no | `{ error, when }` per named error this frame can raise on the path. Drawn in red. |
| `status` | enum | yes | `verified` or `unresolved`. **verified: enum, `unresolved` carries `reason`** |
| `reason` | string | unresolved only | Why the target could not be resolved from the code: a dynamic dispatch, a DI token with several providers, a runtime-registered handler. |
| `candidates` | array | unresolved only | `{ file, line, evidence }` per possible target, each verified like a call site, so the reader sees every door the code could open. **verified** |
| `author_says` | string | no | A comment quoted from the code, only after the code was checked against it, labelled on the page as the author's stated intent. |

**Leaves.** A hop of kind `io` or `external` has no children. The trace records the exact
line the repository hands control away on (`db.insert(...)`, `fetch(...)`, `resend.emails.send(...)`)
and, for `external`, the package and version from the lockfile in `why`.

**Unresolved hops are shown, never guessed.** An `unresolved` hop renders dashed in the
sequence diagram and the stack, with its reason and every candidate linked. When the
unresolved hop is on the main path and the candidates lead to different pages, 16.9 stops
and asks which one to walk, through the wizard tool.

## excerpts.json, written by verify-trace.sh

```json
{
  "verified_at": "2026-09-13T10:41:07Z",
  "root": "/abs/path",
  "repos": [ { "path": "SyanatBackend", "commit": "0f3c1a2", "dirty": ["src/x.ts"] } ],
  "excerpts": [ { "id": "h3", "file": "SyanatBackend/src/…/estimates.service.ts",
                  "start": 41, "end": 78, "lines": ["export async function sendEstimate(", "…"] } ]
}
```

| Field | Rule |
|---|---|
| `verified_at` | UTC timestamp of the run. The page shows it beside the commit. |
| `repos[]` | One entry per git repository a cited file belongs to: `path` relative to `root` (`.` when `root` is the repository), `commit` (short SHA), `dirty` (cited files with uncommitted changes, so the page can say which lines describe a tree that is not yet committed). A file outside any repository is listed under `path: "(no repository)"` with `commit: null`. |
| `excerpts[]` | One per hop, `lines` copied byte for byte from disk by `sed`, never typed. The page renders these, not anything the session remembers. |

## capture.json, written by capture-run.sh

One real run of the traced code: the loaders under `capture/` rewrite, in memory only, every
function whose declaration line sits inside a hop's `range`, the sink records what each call
got, returned or threw and which way each `if`, ternary and `switch` inside it went, and
`capture-aggregate.jq` folds the events into this shape. It is optional, never written by
hand, and what it holds are observations of one run, never the code's contract (16.11, §5).

```json
{
  "version": 1,
  "run": { "mode": "test", "command": "bun test --timeout 30000 src/…/estimates.service.test.ts",
           "runtime": "bun", "started": "2026-09-13T05:41:02Z", "exit": 0, "events": 412, "truncated": false },
  "anchors": [
    { "id": 3, "hop": "h5", "file": "SyanatBackend/src/…/estimates.service.ts", "line": 41,
      "name": "sendEstimate", "kind": "function",
      "calls": [ { "id": 7, "seq": 12, "in": ["wo-1", { "mode": "email", "email": "<email>" }],
                   "out": { "sentAt": "2026-09-13T05:41:03.120Z", "channel": "email" }, "ms": 12.4, "async": true } ],
      "branches": [ { "line": 47, "kind": "branch", "true": 0, "false": 1, "outcomes": [false] },
                    { "line": 52, "kind": "switch", "values": ["email"], "seen": 1 } ] } ],
  "hops": [ { "hop": "h5", "anchors": 2, "calls": 3, "threw": 0, "ms": 14.1 } ]
}
```

| Field | Rule |
|---|---|
| `version` | `1`. **verified** |
| `run.mode` | `test` (the runner waited for the command) or `live` (it was backgrounded and stopped). **verified** |
| `run.command`, `run.runtime`, `run.started` | The command as given, the family of its first word (`bun`, `node`, `other`), the UTC start. |
| `run.exit` | The command's exit code in test mode; `null` after `--stop`. |
| `run.events`, `run.truncated` | Events recorded; `true` when the sink hit its 20 000-event cap and stopped recording. |
| `anchors[]` | One per instrumented function the run loaded: `id` (the sink's index), `hop` and `file` (the hop the function sits in, its file relative to `root`), `line` (the declaration line), `name` (the function's own name, `Class.method`, the variable it is assigned to, or `(fn in <callee>)` for a callback), `kind` (`function`, `arrow`, `method`). **verified: `hop` resolves, `file` is that hop's file, `line` is inside its `range`** |
| `anchors[].calls[]` | One per call: `id`, `seq` (order among every event), `in` (the arguments, masked), then exactly one of `out` (returned, masked), `threw` (`{ error, message }`), `void: true` (fell off the end) or `unfinished: true` (still running when the process ended), `ms` for every finished call, `async: true` when the value settled later. **verified: `in` is an array, one outcome, `ms` on a finished call** |
| `anchors[].branches[]` | One per condition line the run reached: `line`, `kind: "branch"` with `true` and `false` counts and `outcomes` in order, or `kind: "switch"` with the distinct `values` and `seen`. **verified: `line` is inside the hop's `range`, kind is one of the two** |
| `hops[]` | Per hop: `anchors`, `calls`, `threw` and the summed `ms`, the Runtime tab's rows. |

**Masking, before any value reaches disk.** A key matching the secret list (`password`,
`secret`, `token`, `apiKey`, `authorization`, `cookie`, `session`, `otp`, `ssn`, `iban`,
`card`, `privateKey`, `credential`) becomes `<masked>`; an email becomes `<email>`, a phone
`<phone>` (a hyphenated calendar date is not one), a JWT or a long mixed-case token
`<token>`; a string is cut at 200 characters
with `…`; objects stop at depth 4 (`<object>`, `<array n>`), arrays at 20 items (`<n more>`),
objects at 40 keys (`<more>`), and a value over 2 KB is kept as `<N bytes, first 2048> …`.
Functions read `<fn name>`, promises `<promise>`, buffers `<bytes n>`, cycles `<circular>`,
and a class instance carries `<class>`. An error is `{ error, message }` with the message
masked. The runner then runs the law scout's secret patterns (9.5, through
`secret-scan.sh`) over the aggregate and refuses one that still carries a secret.

**The run's environment.** `capture-run.sh` sets `EXPLORE_CAPTURE_TRACE` and
`EXPLORE_CAPTURE_OUT` for the sink, appends `--preload=<capture/preload.bun.ts>` to
`BUN_OPTIONS` and `--import <capture/register.node.mjs>` to `NODE_OPTIONS`, so the command
is run exactly as given and a package script that spawns either runtime is instrumented too.
The rewriter runs on the explored repository's own `typescript`, resolved from `root` the
way its code would resolve it, and that has to be TypeScript 5 with the JS compiler API
(`typescript@7` on npm is the Go compiler and exports none); `EXPLORE_CAPTURE_TYPESCRIPT=<dir>`
names another directory whose `node_modules` holds one, since nothing is ever installed
into the explored repository. A loader that cannot start prints `explore capture: <reason>`
and exits 2 before the command's own code runs.
`bun test` ends its process without firing `exit`, so under it the preload flushes from a
`bun:test` `afterAll`; it recognises the test runner by its entry file being a test file
(the shapes SKILL.md Definitions name), and `EXPLORE_CAPTURE_BUN_TEST=1` or `=0` in the
environment overrides that reading for a layout it does not fit.

**What capture-run.sh checks, in order.** Every refusal prints `capture-run: <what is
wrong>` on stderr and exits 1.

1. The trace parses, is version 2 and its `root` is a directory; jq, the two jq files,
   `secret-scan.sh` and the two loaders are present.
2. After the run, at least one event was recorded; none means the command never entered a
   traced function, and the route says so (16.9, step 6b).
3. The secret scan over the aggregate: a hit deletes the aggregate and the events, since
   both carry the value, and names the line.
4. `capture-verify.jq`: the rules marked **verified** above, and at least one call was
   recorded. A refused aggregate is kept as `capture.rejected.json`, which nothing embeds.
5. Then, and only then, it writes `capture.json` and prints one line: `wrote
   <dir>/capture.json: N anchors, N calls, N branches, N threw, exit E`.

`build-page.sh` runs checks 3 and 4 again on the capture it is given before embedding it, and refuses on either.

## What verify-trace.sh checks, in order

Every check prints `hop <id>: <what is wrong>` (or `trace: <what is wrong>`) on stderr and
the script exits 1 without writing `excerpts.json`. There is no flag to skip a check.

1. `trace.json` parses, `version` is `2`, `root` is a directory.
2. `hops` has 1 to 40 entries; every `id` is unique; `hops[0].id` is `h0` with `from: null`
   and `call: null`; every other hop has `from` naming an earlier hop and a `call` object.
3. `title` ≤ 40 characters; every hop `title` ≤ 60.
4. `entry.kind`, every hop `kind` and every `status` are in their enums; an `unresolved`
   hop carries a non-empty `reason` and at least one candidate.
5. Every hop `file` and every `call.file` and `candidates[].file` exists under `root`.
6. Every `line` is within its file; every `evidence` is a substring of that exact line.
7. Every `range` is in bounds, at most 200 lines and contains `line`; every child hop's
   `call.file` is this hop's file and its `call.line` sits inside this `range`.
8. Every `invoked` line is inside its hop's `range` and is neither blank nor a comment; an
   `invoked` list holds the hop's own `line` and every child hop's `call.line`. When no hop
   carries `invoked` at all, the script still passes and prints `note: no hop carries
   invoked` on stderr, which the route treats as a finding.
9. Every `files[].path` is cited by a hop, and every hop file is listed in `files`.
10. Every hop id in `pseudocode`, `branches.at`, `failure.hops`, `shapes.at`, `decisions`
    and `questions` resolves; `pseudocode` has 1 to 12 steps; `questions` has 3 to 5.
11. Then, and only then, it writes `excerpts.json`.

A trace that fails a check is fixed by re-reading the file it cites and correcting the
trace, never by editing `evidence` until the check passes: the check exists to catch a
citation that was typed from memory.

## Size caps, and what to do past them

| Cap | Limit | Past it |
|---|---|---|
| Hops per page | 40 | Split into chapters: one page per sub-path, each a complete trace, cross-linked through `related`. Ask the user which chapter to build first, through the wizard tool. |
| Lines per excerpt | 200 | Narrow `range` to the lines this path runs; the whole function is one click away in the editor. |
| Pseudocode steps | 12 | Fold: a step names an outcome, not a line. |
| Questions | 3 to 5 | Pick the ones only a reader who followed the path can answer. |

## Slug convention

The slug names the scratch folder and the page file. Derive it from `entry.label`:

| Entry shape | Rule | Example |
|---|---|---|
| HTTP route | `<method-lowercase>-<path>` | `POST /api/work-orders/:id/send-estimate` → `post-api-work-orders-id-send-estimate` |
| CLI command | `cli-<command>` | `bun run cli:create-tenant` → `cli-bun-run-cli-create-tenant` |
| Job | `job-<name>` | `job-heartbeat` |
| UI action | `ui-<component>-<action>` | `ui-sendestimatebutton-click` |
| Other | `<name>` | free-form |

Lowercase ASCII letters, digits and dashes; runs of dashes collapsed; leading and trailing
dashes stripped; at most 80 characters.

## What the page assumes

- `hops` are in execution order and `h0` is first; the stack view nests by `from`.
- Every `call.line` sits inside its parent's excerpt, so every call badge has a line to sit
  on; the verify script is what makes this true.
- `excerpts[].lines` is what the panes show; the page never re-reads a file.
- A hop with `invoked` dims every other line of its excerpt, on a grey band with a dotted
  rail and a tooltip, and its header counts them; a hop without it dims nothing.
- A page carries a `capture` blob only when `build-page.sh` was given a `capture.json` it
  re-verified; the Runtime block under an excerpt, the chips on anchor and branch lines, the
  Runtime tab and the timings on the sequence diagram exist only then. An anchor meets its
  excerpt through `hop` and `line`; a branch chip sits on `branches[].line`.
