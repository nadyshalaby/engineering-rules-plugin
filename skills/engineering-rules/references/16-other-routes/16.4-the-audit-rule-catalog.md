# 16.4 [catalog] The audit rule catalog

## Rule catalog (rule_id → category, severity, engine, source)

This is a MAP, not a copy of the laws. Each row names where the rule is actually defined
(the canonical source resolved in Phase 1) and which engine checks it. The thresholds and
ban tokens are read from those sources at audit time, never hardcoded here. If a project's
`CLAUDE.md` is silent on a rule, this law's floor applies (stricter wins).

Engines:
- **deterministic**, the scanner (the project's own, a session-generated one per 16.7, or
  the law scout's greps in 9.5 as the floor), exact `file:line`. Ten rules are
  zero-false-positive (`confidence: exact`); `ban.bare-error`, `ban.inline-type` and the
  `console.*` half of `clean.debug-artifact` are `confidence: syntactic`, matched exactly in
  syntax, but a true positive needs a one-step scope/threshold check (is this domain code?
  does the type have 2+ props?).
- **linter**, the project's own ESLint/Biome with the cap rule configured; exact.
- **semantic**, a Phase 3 pass that reads the code and judges (16.6).

Categories: **folder-structure**, **code-style**, **file-scoping**, **security**,
**performance**, **testing**, **cleanup**. Design principles (SOLID/YAGNI) report under
**code-style**. The CANONICAL clean-code catalog is 3.4 (stable IDs `style.<domain>.<slug>`,
severity model, detection hints); the `style.*` rows below are coarse groupings that map to
it the way the performance and security rows map to 3.1 and 3.2, and a domain with no coarse
row here (comments, boundaries) is cited straight from 3.4.

### Security

(ten domains, stable IDs `sec.<domain>.<slug>`, severity model,
detection hints, extend never rename). The seven rule ids below are the codebase audit's (16.3) coarse
groupings that predate the catalog; the canonical-source column maps each to its catalog

### Severity → handling

- **critical**, secrets, auth/permission leaks, a focused test. Surface first; fix is usually urgent.
- **high**, zero-tolerance bans, layer leaks, DRY, error handling and async ownership. Strong recommend-to-fix.
- **medium**, caps, SRP, placement. Fix or record a deliberate waiver.
- **low**, naming, magic literals, re-exports. Batch or defer; never auto-apply silently.
