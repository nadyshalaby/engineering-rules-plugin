## Step A. Re-verify

Even though Phase 4 passed. State drifts: other commits, environment changes, hook updates.
Re-run the triad from a clean state and the ship-gate legs Phase 4 marked blocking, and paste
fresh output into the Sprint Review. Anything red stops the phase; re-open Phase 3 (5.1,
"Loop-back"). Do not enter Step B with a red.

## Step B. Choose the landing

**Full mode** offers exactly four options through the wizard tool, the recommended one first,
worded as 13.2 words them: merge to the base branch locally, push and open a pull request,
keep the branch as-is, or discard. Never an open-ended "what next?".

**Quick mode** executes the answer to the handover question from Phase 1 (6.4, Q4). When the
user said *"in place"* or *"leave it"*, the changes stay in the working tree and Step C is a
recorded no-op.

## Step C. Land

Per 13.2. Every commit obeys 9.2: explicit paths, no AI attribution, the project's own voice.

## Step D. Cleanup sweep

Thirteen classes, each checked against the actual diff and the actual environment, never from
memory, each producing a one-line evidence record with a count, zero included:

1. Debug output: logs, prints, dumps added while working.
2. Commented-out code, and any `// removed:` marker.
3. Ownerless debt markers: `TODO`, `FIXME`, `HACK`, `XXX` with no owner or ticket.
4. Dead code: a function, export, file or registration nothing calls.
5. Unused imports, dependencies and environment variables.
6. Scratch files, fixtures, temp directories, and directories left empty by moves.
7. Placeholder values and stub returns that were meant to be replaced.
8. Unrelated changes that snuck in: every path in the diff traces to a task's allowlist.
9. Stale references: cross-references, anchors, and documentation the change made wrong,
   including the work-doc's own path references.
10. Pre-existing errors and law breaks in touched files, surfaced and offered, never silently
    left.
11. Leaked runtime state: dev servers, containers, ports, temporary `.env.local` or fixture
    files staged into the diff.
12. Dead branches created during the task.
13. Focused or skipped tests left on: a `.only`, `fit` or `fdescribe`, or a `.skip`, `xit`,
    `xdescribe` or `test.todo` with no ticket or owner on the line.

The commands and the remediation rule per class are in 13.2. A defect found is fixed now or
filed as a linked Retrospective follow-up with the user's sign-off. Never silently left.

## Step E. Offer a walkthrough where it would help

If the change introduced or altered an entry point (a route, a handler, a CLI command, a job,
a UI action), offer a code walkthrough (16.9) through the wizard tool. When no entry point
was touched, the conditional row is not inserted and the reason is one line in the
reflection. Ask; never assume.

## Step F. Close the record

1. Write the Retrospective (full mode).
2. Print the law self-audit from `SKILL.md` 1.7, filled in. Any `no` re-opens the phase it
   names; the task is not finished.
3. Print the update log (16.13; 13.2, Step F): one block per change a reader would recognise, five
   fields, `----` between blocks, plain language, no mention of the workflow's machinery,
   ending with exactly one follow-up line.
4. **Full mode, one closing edit:** append the self-audit and the update log to the doc, tick
   6c and 6d (and the worktree row when there is one), write `status: done` and the shipped
   fields. Then `git mv docs/work/<slug>.md docs/work/done/<slug>.md`, the last mechanical
   step. The move never precedes the edit. Republish rides the edit where the runtime can.
5. **Quick mode:** the printed self-audit and update log are the whole artifact.

**Historical records are never rewritten.** A changelog entry or a doc sentence that was true
when written stays as it is; the repair goes in the live file.

## Step G. Worktree cleanup

Only when a worktree was used, only on the merge, PR or discard options, never on "keep the
branch as-is", and only after Step F's move. `git worktree remove <path>` from inside the
project repo. If it refuses because of uncommitted changes, stop and ask; never `--force`.

## Voice for the update log

Talk like a person. No phase numbers, no task IDs, no check names, no mention of the
workflow's own machinery, no release-note voice. Say it and stop. Each block under about 120
words. Close with exactly this line, once:

```
Happy to go deeper on any of these, just say which one.
```
